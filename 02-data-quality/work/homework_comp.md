## H1 Правила функции
В ходе работы была реализована функция clean_export(source) для подготовки данных к дальнейшему анализу.
Функция выполняет следующие действия:
Проверяет наличие конфликтующих версий записей с одинаковым известным значением source_row.
Удаляет полностью одинаковые повторные доставки записей.
Удаляет лишние пробелы в поле county_code.
Преобразует необходимые столбцы в числовой формат.
Подсчитывает ошибки преобразования числовых значений.
Проверяет обязательные условия качества данных.
Разделяет записи на подготовленный набор clean и карантин quarantine.
Формирует журнал аудита audit.
В подготовленном наборе остаются записи, для которых известен source_row, значение action_taken равно 1, 2 или 3, сумма loan_amount положительна, а county_code равен 11001.
Записи, нарушающие обязательные условия, отправляются в карантин. Для каждой такой записи указывается причина исключения. Исходные данные не изменяются, поскольку обработка выполняется на копии DataFrame.
## H2 Доход и баланс

Количество записей, известный и неизвестный доход, среднее, единица, баланс и сохранность входа:

Всего подготовленных записей - 6828

Записей с известным доходом - 6485

Записей с неизвестным доходом - 343

Средний известный доход - 237,07 тыс. USD в год
Среднее значение дохода рассчитывалось только по известным значениям. Пропущенные значения не заменялись нулями, поскольку отсутствие информации о доходе не означает, что доход равен нулю.
Количество записей с неизвестным доходом составляет 343. Это необходимо учитывать при интерпретации среднего значения: оно рассчитано не по всем подготовленным записям, а только по тем, для которых доход известен.
## H3 Проверка года и виды проблем
Для проверки правила отчётного года была создана копия исходного набора данных. В первой записи значение activity_year было изменено с ожидаемого года на 2022.
После этого была выполнена проверка, согласно которой все записи должны относиться к 2023 году.
Проверка вернула значение False, что является ожидаемым результатом: в наборе появилась запись с неверным годом.
Этот эксперимент показал, что проверка позволяет обнаруживать нарушение требования к отчётному периоду. При этом исходный набор данных остался неизменным.
